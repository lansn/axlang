## 2026-11-13（续 10）Windows 控制台中文乱码：定位与运行时修复
- 现象：`cxc run` 的中文输出在中文 Windows 控制台显示成 `鐭╁舰 闈㈢Н`。先排除编译环节 —— 用 Python 检查 `--emit=c` 产物，非 ASCII 字节 **0 个**（`cstr()` 把非 ASCII 全转 `\xHH`），所以 C 源码编码与 gcc 的 `-finput-charset` 都无关。
- 真因：cxlang 字符串内部是 UTF-8 字节，`cx_write_stdout` 用 `fwrite` 原样写出，而控制台代码页是 936(GBK) → UTF-8 字节被按 GBK 解释。`cx_env_utf8()` 早已处理环境变量编码，唯独 stdout 漏了。
- 修法：`cxc/rt/cxrt.c` 新增 `cx_console_utf8()` —— `_isatty` 为真时 `SetConsoleOutputCP(CP_UTF8)`（stdout **或** stderr 任一为终端就切）+ `SetConsoleCP(CP_UTF8)`（stdin 为终端时），保存原值并 `atexit` 恢复（`cx_trap` 的 `exit(2)` 同样触发）。`cxrt.h` 加声明；两版 codegen 的 `gen_main_wrapper` 首行都插入 `cx_console_utf8();`（Rust `codegen.rs` + Python `mod_codegen.py`，保持生成 C 一致）。
- **只在 isatty 时切换**是关键：管道/重定向下代码页不动，`runtests.py` 的逐字节比对与 `> out.txt` 的 UTF-8 文件都不受影响。
- 验证手段：工具环境的 stdout 是管道（isatty=0），测不出显示问题，改用 `winpty -Xallow-non-tty` 造伪控制台。证据链：① 伪控制台里 `isatty=64, out_cp=936`，调 `cx_console_utf8()` 后 `out_cp=65001`；② A/B 对照 —— 不调用的程序输出 `鐭╁舰 闈㈢Н 12`，调用的输出 `矩形 面积 12`；③ 管道下调不调用都保持 `out_cp=936`。
- 顺带修：`int main(){...}` 省略 return 时 gcc 冒 `-Wreturn-type` 噪音 → 两版 cc 参数各加 `-Wno-return-type`（cxlang 的 main 允许无 return，是语言层特例，sema 已有检查，不会掩盖真错）。
- 另记：GBK 保存的 `.cx` 直接报 `cxc: 源文件不是合法 UTF-8`（有意为之，不猜编码）。README 新增「Windows 中文显示」一节，并修正「exe 自带 Python 运行时」这句过时说明。

## 2026-11-13（续 12）错误捕获补齐 try/catch/finally（PHP 风格，用户裁定）
- 需求：「错误捕获沿用传统 try catch，参考 PHP」。原设计 10.2 明写"没有 try-catch 块"，捕获只能写整段 match。设计决策：**不引入异常类层级、不跳栈**，在 result<T> 模型上加块语法——块内 result<T> 在需要 T 的位置自动展开（等价隐式 try，`coerce` 里 `try_depth>0 && src==Result(inner) && assignable(inner,dst)` 时改 slot.ty+打 `implicit_try`），失败/throw 跳本块 catch；跨函数仍靠 `try` 后缀逐层传播。
- 语法：`try { } catch (error.Variant e) { } catch (error e) { } finally { }`。catch 按变体过滤（NotFound=1/Invalid=2/Money=3/IO=4），兜底必须最后；可只写 finally。关键字 33→35（catch/finally）。
- 实现：lexer 2 词；ast `Stmt::TryCatch(Box<TryCatchNode>)` + `CatchArm{variant, variant_tok, name, name_tok, body}`；parser `parse_try_catch`（关键坑：**没有 catch/finally 时要把行尾换行留给 expect_term**，否则 `}` 后跟 return 会误报 E2002——用 save/restore `self.p`）；sema `check_try_catch` + `try_depth`（>0 时 throw/try 不再要求函数返回 result）+ E6012（兜底后还有 catch/重复变体）+ E6013（break/continue 跨出 try 块）；codegen `try_stack: Vec<TryCtx>`，生成 `cx_err t_err_N={0}` + `L_catch_N`/`L_fin_N` 标签，catch 链 `if (t_err_N.code==k)`，catch 消费时 `.code=0`。
- codegen 语义细节：①throw 在 try 内 → `emit_defers_from(depth)`（只展开块内 defer，块外的留给函数出口）+ goto；②未匹配 → finally → rethrow，**外层 try 存在就转发给它**（`emit_rethrow` 先查 `try_stack.last()`），否则才走 return fail/main 退出；③**只写 finally 也必须生成 rethrow 段**，否则错误被静默吞掉（TRY-3 抓过这个 bug）；④catch 内 throw 跳 `L_fin`（跳过剩余 catch，防止自己吃自己）；⑤`return` 在 try 内 → 先把值算进临时变量，再按内→外补跑 finally（`emit_finally_chain`，生成期间 `mem::take` 清空 try 栈，finally 里的 throw 属于外层），与 PHP 一致；⑥E6013 的判据是 `loop_depth <= try 进入时的 loop_depth`（**不能用 loop_labels.len()**——它只在带标签循环时入栈），循环在 try 块内部时 break/continue 合法。
- 消警告：catch 变量 `(void)v_e;`；`if (0) { goto L_catch_N; }` 防 unused-label（try 体没有 throw 时标签无引用）。
- 文档同步：文稿 10.2 重写（match 分类 vs try/catch 就近 + 8 条规则）、10.1 条件加"或 try 块内"、第 1 章原则改写、关键字表重排（35 个）、末尾加 ㉛ 变更记录；规格书 §3.4 关键字、语句文法加 try_stmt/catch_clause、E6010 描述、码表补 E6012/E6013；GAP-REPORT 3.4 加第 4 条（超出原设计，用户裁定）；samples/README + README 示例数 10→11。
