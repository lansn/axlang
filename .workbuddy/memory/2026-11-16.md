## axc 0.0.8 — 插值可空值语义收口（E5006 新增）

**起因**：`int main(string[] args)` 里 `Println("v={args.At(0)}")` 输出 `v=?`，不报错也不给值。

**根因**：`codegen_expr.rs::str_lit` 的插值分派只有 int/float/decimal/bool/string/enum 六支，
其余全落 `_ =>` 兜底打 `"?"`；sema 只拦 `TyS::Object`（E5002），`T?` 与数组/class/struct 全漏。
同一件事换写法两样结果：`Println(args.At(0))` 报 E4001，塞进花括号却放行。

**修复**：
- codegen 抽 `push_interp(sb, val, ty, fmt, expr)`，`TyS::Nullable(inner)` 按 `.has` 分支生成
  `if (v.has) push(inner) else push("null")`，递归处理内层。
- `types.rs` 新增 `interp_supported()`（标量/string/enum/可空递归，Unknown/Error/Never 放行防风暴）。
- sema 新增 **E5006**：数组/map/元组/func/class/struct 插值明确报错，兜底降级为带类型注释的防御代码。
- `types.rs` 新增 `strip_nullable()`；`DecLit`/`FloatLit` 落地改按内层判 → 修 `decimal? d = 12.50d`
  误报 E4003、`float? x = 1.5` 误报 E4001。
- `{d:.2}`（d: decimal?）报错文案改为"可空值不能直接加格式说明符，先判空取出"。

**设计立场**（写进文稿 6.2/11.2、规格书 §13.7）：插值只做显示、结果一定是 string，不产生可空值逃逸，
所以花括号里的位置放行；赋值/传参仍照常要求判空。复合类型"怎么显示"是未定设计题，宁可 E5006 也不静默打 `?`。
