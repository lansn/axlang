## 模块成员改回 PascalCase（axc 0.0.24，166/166，㊾）

用户对 0.0.23 的"模块函数也小写"犹豫不决（C# 驼峰 vs snake_case），我给出建议并被采纳：**分界线从"函数 vs 方法"移到"有没有那个点"**——`名字(...)` 全小写（值层一等函数），`X.名字(...)` 一律 PascalCase，不问 X 是模块、类型还是变量。决定性论据是**现状自相矛盾**：`string.FromCodepoint()`（PascalCase，因 string 是类型）与 `io.read_line()`（小写，因 io 是模块）语法同形不同拼法，读者得先知道 X 是什么；而 `string` 既是类型又是模块，两条入口拼写还得一致。次要论据：C# 没有模块函数只有静态类成员（Console.WriteLine/Math.Sqrt）；Rust 的 `std::fs::read_to_string` 敢用小写是因为 `::` 在视觉上宣告"路径不是成员"，axlang 只有 `.`。

改名：io.ReadLine/ReadFile、file.Open/Create/Append、json.Parse/Stringify、math.Equals/Compare、db.Query、time.NowMs（string.FromCodepoint 本已对）。print/println 保持小写——`var f = print` 合法而 `var x = io` 编译错误，命名如实反映这条已存在的语义差异。

**新增点名式迁移提示**：`pascal_member(name)` 把 read_line → ReadLine（split('_') 逐段首字母大写）再回 `module_sig` 核对，命中才报"模块成员一律 PascalCase：`io.read_line` 请写 `io.ReadLine`"；真拼错（`io.foo`）仍报笼统"没有符号"，不瞎猜。位置：sema/expr.rs 顶层 pub fn + sema/member.rs check_module_call 的 None 分支。
